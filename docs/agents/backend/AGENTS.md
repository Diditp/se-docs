# AGENTS.md — Node.js & TypeScript Backend Rules

> Domain rules for REST API services in Node.js + TypeScript. Load together with the global `/AGENTS.md`,
> `docs/agents/database/AGENTS.md` for data access, and `docs/agents/security/AGENTS.md` for auth.
> Default stack assumed: Node.js LTS, TypeScript `strict`, Express or Fastify (NestJS: same rules, mapped to
> module/controller/provider), Zod for validation, PostgreSQL, Redis, BullMQ, pino, Vitest/Jest + supertest.

## Scope

Applies to `src/`, `tests/`, `package.json`, `tsconfig*.json`, and API contract files (`docs/api/openapi.yaml`).

## 1. Coding Standards

- **MUST** keep `tsconfig` `strict: true`; **MUST NOT** use `any` (use `unknown` + narrowing) or `@ts-ignore` without a reason comment. *Why:* types are the cheapest tests.
- **MUST** use `async/await` and handle every promise (no floating promises — lint `no-floating-promises`).
- **MUST** validate configuration at startup with a schema (Zod) and export a typed `config` object; never read `process.env` elsewhere. *Why:* misconfiguration fails fast and in one place.
- **MUST** use ES modules and named exports; one responsibility per module.
- **SHOULD** keep functions pure where possible and pass dependencies explicitly.

## 2. Project Structure

```
src/
  app.ts                    # create app: middleware, routes, error handler
  server.ts                 # start server, graceful shutdown (SIGTERM/SIGINT)
  config/                   # env schema + typed config
  shared/                   # errors/, middleware/ (auth, request-id, error), logger, db, cache, http-client
  modules/<module>/
    <module>.routes.ts      # routing + auth/permission middleware
    <module>.controller.ts  # parse/validate input → call service → map to HTTP response
    <module>.service.ts     # business rules + transactions (no req/res)
    <module>.repository.ts  # ALL database access for this module
    <module>.schemas.ts     # Zod request/response schemas
    <module>.types.ts
  jobs/                     # queue processors
db/migrations/              # ordered, immutable after merge
tests/unit/<module>/ · tests/integration/<module>/ · tests/factories/
docs/api/openapi.yaml       # API contract (source of truth)
```

## 3. Architecture & Design Principles

- **MUST** keep layers strict:
  - Controller: no SQL, no business rules. Validates input, calls service, shapes response.
  - Service: no `express`/`fastify` imports, no `req`/`res`; receives validated DTOs plus a user context `{ userId, role, tenantIds }`; owns transactions.
  - Repository: the only place with queries; accepts an optional transaction handle.
  - *Why:* each layer is testable alone and business rules have one home.
- **MUST NOT** access another module's repository; call its service or publish an event. *Why:* module boundaries allow later extraction.
- **MUST** design APIs contract-first: update `docs/api/openapi.yaml`, then implement. Changes inside `/v1` are additive only.
- **MUST** make create/payment endpoints idempotent via `Idempotency-Key` (stored per user + key with the original response) and unique constraints.
- **MUST** move slow or retryable work (emails, notifications, reports, third-party sync) to background jobs; jobs are idempotent with retry + backoff and a dead-letter strategy.
- **MUST** implement graceful shutdown: stop accepting connections, finish in-flight requests, close DB/queue connections, exit within a timeout.
- **File uploads:** medium/large files go directly to object storage via short-lived presigned URLs; object keys are generated by the server (tenant-prefixed); content is verified (magic bytes, size) and images re-encoded in a worker before being marked `ready`; private files are served with short-lived signed URLs after authorization.
- **Background jobs:** job payloads carry IDs only; status lives in the database; job IDs are deterministic for deduplication; permanent failures use a non-retryable error; recurring jobs use a coordinated scheduler (never a cron inside every API instance). Long-running endpoints return `202` + a status resource.
- **Client versions:** read `X-App-Version`/`X-Platform`, record them in metrics, and return `426` with `APP_UPDATE_REQUIRED` below the minimum supported version. Deprecated endpoints send `Deprecation`/`Sunset` headers.

### API conventions

- Paths `/v1/<plural-resource>` (kebab-case); domain actions as `POST /v1/orders/{id}/void`.
- JSON `snake_case` (or the existing project convention — never mix); timestamps ISO 8601 UTC; money integer minor units.
- Success: `{ "data": …, "meta": … }`. Lists: cursor pagination (`limit` default 20, max 100, `next_cursor`).
- Errors: RFC 9457 Problem Details (`application/problem+json`) with `request_id`; never stack traces.
- Status: 201 + `Location`, 202 for async, 204 for empty, 400/422 input, 401, 403, 404, 409, 429 + `Retry-After`.

## 5. Dependency Management

- **MUST** use `npm ci` with the committed `package-lock.json`; **MUST NOT** mix package managers.
- **MUST** justify new dependencies (weekly downloads, maintenance, transitive size, license, known CVEs) and prefer Node built-ins (`node:crypto`, `fetch`, `node:test` where adopted).
- **MUST** keep runtime vs dev dependencies correct; production image installs runtime deps only.
- **MUST** run `npm audit --omit=dev` in CI; fix high/critical findings or document the exception.

## 6. Error Handling

- Services throw typed domain errors (`NotFoundError`, `ConflictError`, `ForbiddenError`, `ValidationError`); a single error middleware maps them to Problem Details.
- Every async route handler forwards errors (`next(err)` or an `asyncHandler` wrapper / framework native async support).
- Unknown errors → 500 with a generic message; log once with `request_id`, user id, route, and error stack.
- `unhandledRejection`/`uncaughtException`: log and exit so the orchestrator restarts a clean process.
- Outgoing HTTP calls: timeouts, retries only for idempotent requests with backoff + jitter, circuit breaker for unstable dependencies.

## 7. Testing Requirements

- Service: unit tests with fake repositories — success, each domain error, authorization rules.
- Endpoint: integration tests (supertest + real PostgreSQL in Docker) for 2xx, 400/422, 401, 403, and cross-tenant access (must return 404).
- Every bug fix: regression test. Test data via factories; tests independent of order.
- Contract: response shapes validated against Zod/OpenAPI schemas.
- Full rules: `docs/agents/testing/AGENTS.md`.

## 8. Security Requirements

- `requireAuth` verifies JWT signature, `alg` (whitelist), `iss`, `aud`, `exp`; `requirePermission(...)` enforces roles.
- **MUST** scope every tenant/user data query with ids from the token, never from the request body (prevents BOLA/IDOR).
- **MUST** use `.strict()` schemas (reject unknown fields) to prevent mass assignment.
- **MUST** hash passwords with Argon2id (or bcrypt with adequate cost); rate-limit auth, OTP, and expensive endpoints.
- **MUST** set security headers (`helmet`), strict CORS allowlist, body size limits.
- **MUST** redact secrets in logs (`authorization`, `cookie`, `password`, `token`, `refresh_token`, `pin`).
- **MUST** verify webhook signatures (HMAC, constant-time compare) and process webhooks idempotently.
- **GraphQL (when used):** authorize inside resolvers/services per object (not only at the gateway); enforce max query depth/complexity and a max page size; disable introspection for private APIs; create DataLoaders **per request** (a global DataLoader leaks cached data between users). Return stable `extensions.code` values for errors.
- **BaaS (Firebase/Supabase, when used):** every Supabase table exposed to clients **MUST** have Row Level Security enabled with tested policies; Firestore/Storage rules **MUST NOT** allow open read/write. `service_role`/service-account credentials live only on the server. Prices, stock, balances, and permissions are computed in functions/server code, never trusted from the client.
- **Real-time (WebSocket/SSE):** authenticate at handshake with a short-lived token, authorize every room/topic subscription, validate every inbound message, and apply per-connection rate limits.
- Full rules: `docs/agents/security/AGENTS.md`.

## 9. Performance Considerations

- **MUST NOT** use `*Sync` APIs or CPU-heavy loops on the request path; use a worker pool or background job.
- **MUST** reuse a DB connection pool and bound concurrency of outbound calls.
- **MUST** paginate lists and limit payload size; stream large exports.
- **SHOULD** cache read-heavy, rarely-changing data in Redis with explicit TTL and invalidation on write.
- **SHOULD** monitor event loop lag, p95/p99 latency, and error rate per route.

- List endpoints **MUST** have a server-side max `limit`; use cursor (keyset) pagination with a unique tie-breaker for mobile lists; sort/filter fields come from a whitelist.
- Cache with an explicit TTL and an invalidation strategy (delete or bump a versioned key **after** commit); cache keys for per-user/tenant data include the tenant/user id; send `Cache-Control: private` for personal data.
- WebSocket servers send heartbeats, terminate dead connections, and publish cross-instance events through Redis pub/sub or a broker; events carry a sequence so clients can catch up after reconnect.

## 10. Anti-Patterns to Avoid

| Do not | Do instead | Why |
| --- | --- | --- |
| SQL in controllers | Repository | Layering, testability |
| `res.status()` in services | Throw domain error | Transport-agnostic services |
| `200 { success: false }` | Proper status + Problem Details | Clients, caching, monitoring |
| Trusting `userId`/`role`/price from body | Token context; server-side pricing | Security |
| HTTP calls inside DB transactions | Outbox / after commit | Lock time, consistency |
| `await` in loops for independent calls | `Promise.all` with a limit | Latency |
| Editing merged migrations | New migration | Environments diverge |

## 12. Code Review Checklist

- [ ] Layers respected (controller → service → repository)?
- [ ] Input validated strictly; output shape matches contract?
- [ ] Every query tenant-scoped; permission middleware present?
- [ ] Errors typed and mapped; nothing leaks internals?
- [ ] Idempotency for create/payment/webhook paths?
- [ ] No N+1, unbounded queries, or blocking calls?
- [ ] Graceful shutdown and timeouts preserved?
- [ ] Tests cover success, validation, auth, and regression?
